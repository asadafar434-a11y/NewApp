# T-034: ЮKassa — вебхук статусов

**Фаза:** 4 · **Оценка:** 4ч · **Зависит от:** T-033 · **Статус:** todo

## Цель
Оплата тестовой картой переводит Payment в succeeded автоматически; повторные вебхуки безопасны.

## Контекст
[05-api.md](../05-api.md#вебхук-юkassa): не доверяем телу — подтверждающий GET в API ЮKassa.
Для локальной разработки вебхук недоступен снаружи — режим поллинга.

## Что сделать
- [ ] `POST /webhooks/yookassa` (вне auth-middleware): проверка IP по списку диапазонов ЮKassa (env-флаг отключения для тестов) → getPayment(object.id) → маппинг статуса → обновление Payment (идемпотентно: финальный статус не перезаписывается) → publish SSE `payment:status` → Notification (задел, полноценно в T-042)
- [ ] Fallback для local: `POST /payments/:id/refresh` (owner) — тот же getPayment вручную
- [ ] paidAt при succeeded
- [ ] Vitest: succeeded-вебхук обновляет; повторный — no-op; canceled после succeeded — игнор + warn-лог; чужой/несуществующий id — 200 без изменений

## Затрагиваемые файлы
- `apps/api/src/routes/webhooks.routes.ts` — создать
- `apps/api/src/services/payments.service.ts` — изменить

## Критерии приёмки
- [ ] На staging (после T-046): реальная тестовая оплата → succeeded без ручных действий
- [ ] Локально: оплата → «Обновить статус» → succeeded
- [ ] Идемпотентность покрыта тестами

## Как проверить
Локально: T-033 флоу + refresh. Вебхук настроить в ЛК ЮKassa на staging-URL при T-046.

## Подводные камни
ЮKassa шлёт вебхук до редиректа пользователя обратно — UI не должен полагаться на return.
Ответ вебхуку всегда 200 (иначе ретраи копятся); ошибки — в Sentry.
