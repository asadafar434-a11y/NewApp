# T-021: Статусы специалиста — валидатор переходов + таймлайн

Смена статуса валидируется по типу заявки, пишется в лог и показывается таймлайном в профиле.

## Контекст

`POST /specialists/:id/status` — [05-api.md](../05-api.md).

- [ ] GET специалиста отдаёт statusChanges (уже в T-019) — фронт: таймлайн в CandidateDetail (существующая стилистика, mono-шрифт дат)

## Затрагиваемые файлы

- `apps/web/src/pages/Hiring.tsx` (CandidateDetail) — изменить

## Критерии приёмки
- [ ] hire-специалист проходит new→contacted→scheduled→interviewed→hired; consult — свой цикл
- [ ] Прямой curl с недопустимым статусом → 400
- [ ] Таймлайн отображает историю с датами

## Как проверить
UI-цепочка + `curl -X POST .../status -d '{"status":"hired"}'` из состояния new → 400.

## Подводные камни
`rejected` доступен из любого нефинального статуса обоих циклов. Транзакция обязательна —
иначе рассинхрон статуса и лога.
