Сиды → UI: поиск «Анна», фильтр hired, правка зарплаты, F5.

## Подводные камни
Дебаунс поиска (300 мс), иначе запрос на каждый символ. Не терять существующие стили/анимации —
менять только источник данных, не разметку.

## Осознанные упрощения и находки
- **Числа в чипсах статуса убраны.** Точный подсчёт по каждому статусу потребовал бы либо
  отдельного агрегирующего запроса (нет в контракте 05-api.md), либо второго
  нефильтрованного fetch только ради чисел. Оставлен один настоящий серверный запрос —
  он же список, он же источник счётчика «Все (N)» текущей выборки.
- **Смена статуса пока не подключена к бэкенду.** `updateSpecialistSchema` сознательно не
  включает `status` (см. `packages/shared/src/schemas/specialist.ts`) — переходы статусов
  с логом (`StatusChange`) отдельная задача, T-021. Пилюли статуса в `CandidateDetail`
  оставлены как визуальный индикатор (не кнопки), с подсказкой про T-021 — чтобы не ломать
  разметку и не имитировать сохранение, которого на самом деле нет.
- **`lastActive` заменён на `Добавлен: {createdAt}`.** Бэкенд не хранит «последнюю активность»
  специалиста (этого не было в схеме и не появится без отдельного трекинга) — честнее
  показать реальное поле, чем выдумывать данные.
- **`ScheduledCall` (созвоны) остаётся локальным моком.** Реальный `/calls` API — задача T-026;
  до неё расписание звонков в Hiring работает как раньше, только `candidateId` теперь строка
  (реальный id специалиста), а не число из старого мока.
