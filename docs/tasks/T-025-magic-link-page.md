# T-025: Magic-ссылка — письмо и страница специалиста

**Фаза:** 3 · **Оценка:** 4ч · **Зависит от:** T-023 · **Статус:** todo

## Цель
Специалист получает email со ссылкой /chat/:token, отвечает владельцу и видит свои звонки без регистрации.

## Контекст
[ADR-0002](../adr/ADR-0002-magic-link-chat.md); эндпоинты `public/chat/:token/*` —
[05-api.md](../05-api.md); шаблон `chat-invite` — из T-013.

## Что сделать
- [ ] `services/specialist-access.service.ts`: `ensureToken(specialistId)` — живой токен или новый (32 байта, 30 дней); вызывается при первом сообщении owner в диалоге (и при каждом следующем, если токенов живых нет) → отправка chat-invite
- [ ] Публичные роуты: GET /public/chat/:token (компания, имя владельца, сообщения, звонки специалиста), POST .../messages (sender=specialist; owner-сообщения → delivered), GET .../events (SSE своего диалога)
- [ ] Прочтение: открытие страницы специалистом → owner-сообщения read (publish статуса владельцу)
- [ ] Фронт: роут `/chat/:token` вне Root — минимальный экран (логотип, тред, звонки, поле ввода) в стилистике дизайн-токенов
- [ ] Vitest: протухший/несуществующий токен → 401; сообщение специалиста доходит владельцу

## Критерии приёмки
- [ ] Первое сообщение специалисту пишет ссылку в лог (dev); переход — чат работает в инкогнито
- [ ] Ответ специалиста мгновенно у владельца (SSE), статусы delivered/read меняются корректно
- [ ] Ссылка с истёкшим токеном — экран «ссылка устарела, запросите новое письмо у владельца»

## Как проверить
Обычное окно (владелец) + инкогнито (специалист по ссылке из лога): переписка в обе стороны.

## Подводные камни
Rate limit публичных роутов строже (30/мин на токен). В SSE специалиста не публиковать события
других диалогов компании — подписка по conversationId, не companyId.
