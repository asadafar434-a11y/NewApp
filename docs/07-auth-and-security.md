# 07 — Аутентификация и безопасность

## Флоу

### Регистрация
1. `/auth` (signup): имя, email, пароль, компания → Better Auth `signUp.email`.
2. Хук `after sign-up`: создать `Company { ownerId, name }`.
3. Better Auth шлёт письмо подтверждения (через `lib/email` → Unisender Go).
4. До `emailVerified=true` middleware пускает только на `/verify-email` и auth-эндпоинты;
   API отвечает 403 `EMAIL_NOT_VERIFIED`.
5. Клик по ссылке из письма → verified → редирект в `/`.

### Вход / выход
`signIn.email` → httpOnly-кука сессии. Выход — `signOut`. Неверные данные — общая ошибка
«Неверный email или пароль» (без раскрытия, существует ли email).

### Сброс пароля
`/reset-password`: запрос ссылки (ответ одинаковый, существует email или нет) → письмо →
форма нового пароля → **инвалидация всех сессий** пользователя.

### Magic-ссылка специалиста
1. Первое сообщение владельца специалисту → генерируется `SpecialistAccessToken`
   (32 случайных байта, base64url, срок 30 дней) → email со ссылкой `/chat/:token`.
2. Каждое новое письмо-уведомление создаёт **новый** токен (старые живут до своего expiry).
3. Страница `/chat/:token` работает без логина; токен — единственный секрет, все
   `public/chat/:token/*` эндпоинты валидируют его при каждом запросе (существует, не истёк,
   специалист и компания не soft-deleted).
4. Скомпрометированный токен отзывается удалением записи (функция в admin).

## Конфигурация Better Auth (ориентир)

```ts
// apps/api/src/lib/auth.ts
export const auth = betterAuth({
  database: prismaAdapter(prisma, { provider: 'postgresql' }),
  emailAndPassword: {
    enabled: true,
    requireEmailVerification: true,
    minPasswordLength: 8,
    sendResetPassword: async ({ user, url }) => sendEmail('reset', user.email, { url }),
  },
  emailVerification: {
    sendOnSignUp: true,
    sendVerificationEmail: async ({ user, url }) => sendEmail('verify', user.email, { url }),
  },
  session: {
    expiresIn: 60 * 60 * 24 * 30,      // 30 дней
    updateAge: 60 * 60 * 24,           // скользящее продление раз в сутки
    cookieCache: { enabled: true, maxAge: 300 },
  },
  advanced: { useSecureCookies: true }, // prod
  trustedOrigins: [env.WEB_ORIGIN],
})
```

Смена пароля → `revokeOtherSessions: true`.

## Матрица прав

| Действие | owner | admin | magic-токен |
|---|---|---|---|
| CRUD своих заявок/специалистов/финансов/кампаний/ops | ✅ | — | — |
| Чтение/отправка в своих диалогах | ✅ | — | только свой диалог |
| Просмотр своих звонков | ✅ | — | только свои |
| Создание платежа | ✅ | — | — |
| Возврат платежа | — | ✅ | — |
| AI-эндпоинты | ✅ (в лимите) | — | — |
| Список компаний, отзыв токенов | — | ✅ | — |

**Где проверяются права:** только в `services`. Каждый метод сервиса первым аргументом получает
`ctx = { companyId, userId, role }` из middleware и обязан фильтровать по `companyId` в каждом
запросе к репозиторию. Репозитории принимают `companyId` явным параметром — запрос «без компании»
невозможен по сигнатуре. Это главная защита от IDOR.

## Безопасность

| Область | Решение |
|---|---|
| CORS | Только `WEB_ORIGIN`; `credentials: true`; фронт и API на одном домене второго уровня |
| CSRF | Кука `SameSite=Lax` + проверка Origin-заголовка на мутациях (middleware); вебхук ЮKassa вне проверки (своя защита) |
| Rate limiting | См. [05-api.md](05-api.md); auth и public-чат — самые строгие |
| Валидация ввода | Zod на каждом эндпоинте, вход И выход; `z.string().max()` везде — защита от раздувания БД |
| Пароли | Хэширование — Better Auth (scrypt); min 8 символов |
| Секреты | Только env-переменные на VPS; в репозитории — `.env.example` без значений |
| SQL-инъекции | Prisma (параметризация); сырой SQL запрещён конвенцией |
| XSS | React экранирует по умолчанию; `dangerouslySetInnerHTML` запрещён; AI-ответы рендерятся как текст/markdown через безопасный рендерер |
| SSRF | Наружу ходим только на фиксированные хосты (ЮKassa, Claude, Unisender, S3); URL от пользователей никуда не фетчим |
| Файлы | Presign только для `application/pdf` и image/*; лимит 10 МБ в policy; ключи вида `companies/{companyId}/...` — чужие ключи недоступны |
| Заголовки | `secureHeaders()` Hono (CSP, X-Frame-Options и т.д.) |
| Логи | Pino; в логи не пишутся пароли, токены, тела AI-диалогов |

## Персональные данные (152-ФЗ)

- Субъекты: владельцы (email, имя) и **специалисты** (ФИО, email, телефон, резюме) —
  вводятся владельцем, платформа — оператор ПД.
- Хранение и обработка — только на серверах в РФ: VPS (Timeweb Cloud) + S3 РФ-провайдера.
  Claude API получает данные диалогов — в согласии на обработку и политике конфиденциальности
  явно указать передачу текстов AI-провайдеру; ПД специалистов в AI-промпты передаём
  минимально (имя, роль, навыки — без телефона/email).
- Документы к запуску: политика конфиденциальности, согласие на обработку ПД (чекбокс при
  регистрации), согласие в письме специалисту (первое письмо содержит ссылку на политику).
- Удаление аккаунта: soft-delete 30 дней → полное каскадное удаление (данные специалистов уходят
  вместе с компанией); файлы S3 чистятся тем же джобом.
