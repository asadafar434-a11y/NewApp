# ADR-0005: SSE вместо WebSocket для реалтайма

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
Нужен реалтайм: входящие сообщения чата (владельцу и специалисту), статусы платежей,
стриминг AI-ответов. Масштаб — ≤50 одновременных пользователей, один инстанс API.

## Решение
Server-Sent Events: `GET /events` (владелец), `GET /public/chat/:token/events` (специалист);
стриминг AI — тоже SSE-чанки в ответе POST. Отправка сообщений — обычный POST.
Реестр подписчиков — in-memory Map по companyId/conversationId (`lib/sse`).

## Альтернативы
- **WebSocket** — двунаправленность не нужна (исходящие идут POST'ом); сложнее прокси/reconnect.
- **Polling** — проще, но задержки и лишняя нагрузка; SSE ненамного сложнее.

## Последствия
- (+) Нативный EventSource с авто-reconnect; проходит через Caddy без настроек; куки работают.
- (−) In-memory реестр не переживает рестарт и не масштабируется горизонтально — при переходе
  на >1 инстанс потребуется Redis pub/sub (осознанно отложено).
- Лимит открытых SSE-соединений мал (≤100) — не проблема для Node.
