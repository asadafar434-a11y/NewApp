# ADR-0002: Специалист без аккаунта — доступ к чату по magic-ссылке

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
В v1 специалисты — записи, создаваемые владельцем; кабинета специалиста и маркетплейса нет
(v2). Но чат владелец ↔ специалист двусторонний: специалист должен отвечать и видеть звонки,
не регистрируясь.

## Решение
При первом сообщении владельца специалисту уходит email (Unisender Go) с magic-ссылкой
`/chat/:token`. Токен: 32 случайных байта base64url, срок 30 дней; каждое новое письмо создаёт
новый токен. Страница — облегчённая (без Root-layout): тред чата + назначенные звонки.
Все публичные эндпоинты `/public/chat/:token/*`, включая SSE, валидируют токен на каждом запросе.

## Альтернативы
- **Полноценная регистрация специалиста** — двусторонний маркетплейс, растит скоуп v1 в разы;
  отклонено, план на v2.
- **Ответы по email (reply-to parsing)** — хрупкий парсинг, нет реалтайма и статусов прочтения.
- **Бессрочный токен** — проще, но компрометация ссылки давала бы вечный доступ к переписке.

## Последствия
- (+) Нулевой порог входа для специалиста; весь функционал чата переиспользуется.
- (−) Ссылка = секрет: пересланное письмо даёт доступ к диалогу. Смягчение: срок 30 дней,
  отзыв токена админом, в письме предупреждение «не пересылайте».
- Миграция на кабинеты в v2 проста: токены заменяются сессией, публичные эндпоинты — приватными.
