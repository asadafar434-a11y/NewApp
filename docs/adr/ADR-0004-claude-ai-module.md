# ADR-0004: Единый AI-модуль поверх Claude API с помесячными лимитами

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
AI — ядро ценности: чаты (NewTask, Hiring), match-оценка, анализ финансов/маркетинга,
ops-отчёты. Ключ — платформенный (владельцы свои ключи не вводят), значит расходы на токены —
наши, их нужно ограничивать. Пользователи в РФ — прямой доступ к api.anthropic.com может
требовать сетевого обхода.

## Решение
Один модуль `apps/api/src/lib/ai`:
- обёртка над `@anthropic-ai/sdk` (модель из env `AI_MODEL`, base URL из `ANTHROPIC_BASE_URL`);
- функции: `streamChat(системный контекст, история)`, `complete(prompt, jsonSchema)` для
  структурных ответов (match-оценка, finance issues);
- перед каждым вызовом — проверка `TokenUsage[companyId, month] < AI_MONTHLY_TOKEN_LIMIT`,
  после — атомарный инкремент фактических токенов из ответа API; превышение → 422 TOKEN_LIMIT;
- системный контекст компании собирается сервисом (название, заявки, агрегаты) — ПД специалистов
  передаётся минимально (имя, роль, навыки; без email/телефона).

Стриминг чатов — SSE-чанки до клиента. Если прямой доступ к API из РФ-VPS нестабилен —
`ANTHROPIC_BASE_URL` переключается на собственный тонкий прокси на зарубежном узле; код не меняется.

## Альтернативы
- **Ключи владельцев (BYOK)** — снимает наши расходы, но убивает UX онбординга; v2-опция.
- **Очередь для AI-вызовов** — не нужна: вызовы синхронные в рамках запроса, стриминг закрывает UX.
- **Локальные модели** — качество и эксплуатация не соответствуют MVP.

## Последствия
- (+) Все расходы управляются одной env-переменной лимита; замена модели/эндпоинта без правок кода.
- (−) Лимит общий на компанию — одна «прожорливая» фича может съесть месячный бюджет компании;
  на MVP приемлемо, гранулярные лимиты отложены.
- Тесты мокируют модуль целиком; реальные вызовы — только ручная проверка.
