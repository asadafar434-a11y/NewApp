# ADR-0003: Платежи через ЮKassa, выплаты специалистам вручную

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
Оплата консультаций должна происходить на платформе (решение владельца продукта).
Пользователи в РФ → Stripe недоступен. Нужны чеки (54-ФЗ). Команда — один разработчик.

## Решение
ЮKassa, redirect-флоу: `POST /payments` создаёт платёж по цене из `Request.priceKopecks`
(цену клиент не передаёт), возвращает `confirmationUrl`; статус обновляется вебхуком
с подтверждающим GET в API ЮKassa. Чеки — встроенная фискализация ЮKassa.
Деньги приходят на счёт платформы; выплаты специалистам в v1 — вручную, вне платформы;
комиссия (`PLATFORM_COMMISSION_PCT`) фиксируется в записи платежа. Возвраты — админ через ЮKassa.

## Альтернативы
- **CloudPayments** — сопоставимо; ЮKassa выбрана за распространённость и фискализацию из коробки.
- **Сплит-платежи (ЮKassa «Безопасная сделка» / маркетплейс-решения)** — автоматические выплаты
  специалистам, но требует онбординга специалистов (в v1 у них нет даже аккаунта); отложено до v2.
- **Оплата вне платформы** — теряем монетизацию и контроль; отклонено владельцем.

## Последствия
- (+) Быстрая интеграция; чеки автоматически; цена защищена от подмены на клиенте.
- (−) Ручные выплаты не масштабируются — приемлемо до десятков консультаций/мес; нужен
  договор-оферта и юрлицо/ИП для подключения боевого магазина ЮKassa (организационная задача
  до запуска платежей в прод).
- Идемпотентность вебхука обязательна (повторные доставки).
