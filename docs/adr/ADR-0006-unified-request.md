# ADR-0006: Единая модель Request для найма и консультаций

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
Продукт расширился: не только найм, но и точечные платные консультации от профи. UI построен
вокруг воронки кандидатов; консультация повторяет большую часть флоу (специалист, чат, звонок),
отличаясь оплатой и коротким циклом статусов.

## Решение
Одна сущность `Request` c `type: hire | consult` (+ `priceKopecks` для consult). `Specialist`
привязан к одной заявке (1-N). Один enum `SpecialistStatus`; допустимые переходы зависят от
типа заявки и валидируются в сервисе:
- hire: `new → contacted → scheduled → interviewed → hired | rejected`
- consult: `new → contacted → consult_scheduled → consult_done | rejected`

Оплата (`Payment`) ссылается на Request типа consult. Итог консультации — `resultNote` звонка.

Сюда же: фронтенд остаётся на react-router v7 (миграция на TanStack Router из стека отложена
до v2 — нулевая ценность для MVP при заметном риске регрессий существующего UI).

## Альтернативы
- **Отдельные сущности Vacancy и Consultation** — чище семантика, но дублирует чат/звонки/статусы
  и раздваивает UI; отклонено.
- **Отдельный enum статусов для консультаций** — два поля с частично общими значениями,
  больше кода валидации без выгоды.

## Последствия
- (+) Один UI-флоу (Hiring-экран) обслуживает оба типа; переиспользование чата, звонков, AI-match.
- (−) Enum содержит статусы «не своего» типа — валидатор переходов обязателен, покрыть тестами.
- Отчёт по типам заявок тривиален (фильтр по type).
