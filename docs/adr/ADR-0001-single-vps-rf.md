# ADR-0001: Один VPS в РФ вместо Railway/Vercel

**Статус:** принято · **Дата:** 2026-07-30

## Контекст
Пользователи — в РФ; специалисты — субъекты персональных данных (ФИО, телефоны, резюме),
что требует хранения ПД на территории РФ (152-ФЗ). Зафиксированный стек предлагал
Railway + Vercel с альтернативой «VPS + Docker Compose + Caddy». Бюджет ≤15 000 ₽/мес.

## Решение
Один VPS (Timeweb Cloud, 4 vCPU/8 ГБ, Ubuntu 24.04) в РФ. На нём: Caddy (TLS, статика фронта,
reverse proxy), два compose-стека (staging, prod) с API-контейнером и Postgres каждый.
Vercel не используется — фронт раздаёт Caddy.

## Альтернативы
- **Railway + Vercel** — данные вне РФ, нарушение 152-ФЗ; отклонено.
- **Российское управляемое облако (Yandex Cloud, VK Cloud)** — соответствует 152-ФЗ, но дороже
  и сложнее для одного разработчика без опыта бэкенда; отложено как путь роста.
- **Два VPS (staging отдельно)** — чище изоляция, но дороже и больше администрирования; на
  нашем масштабе не нужно.

## Последствия
- (+) ПД в РФ; предсказуемая цена ~2 500 ₽/мес; полный контроль; фронт и API на одном домене
  (куки без кросс-доменных сложностей).
- (−) Самостоятельное администрирование (обновления, UFW, бэкапы); нет автоскейла — при росте
  мигрируем в управляемое облако (Docker-образы переносимы).
- Staging и prod делят ресурсы — нагрузочные эксперименты на staging могут аффектить prod;
  приемлемо для MVP.
