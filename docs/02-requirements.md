# 02 — Требования и скоуп MVP

## Функциональные требования (v1)

### Auth
- FR-1. Регистрация: имя, email, пароль, название компании. Better Auth.
- FR-2. Подтверждение email **обязательно**: до подтверждения доступен только экран «подтвердите почту» с повторной отправкой.
- FR-3. Вход email+пароль; сброс пароля по email; выход.
- FR-4. Сессии httpOnly-куки, 30 дней со скользящим продлением; смена пароля инвалидирует все сессии.

### Заявки и специалисты (ядро)
- FR-5. CRUD заявок (`Request`): тип `hire`/`consult`, название, описание; для `consult` — цена.
- FR-6. CRUD специалистов: профиль (имя, роль, опыт, локация, зарплата/ставка, источник, навыки, о себе, email, телефон, портфолио, доступность, часовой пояс), привязка к одной заявке.
- FR-7. Загрузка резюме (PDF ≤10 МБ) и аватара специалиста; S3 + presigned URLs.
- FR-8. Статусный цикл найма: `new → contacted → scheduled → interviewed → hired | rejected`; для консультаций: `new → contacted → consult_scheduled → consult_done | rejected`. Каждая смена пишется в лог (таймлайн в профиле).
- FR-9. AI match-оценка (0–100) специалиста относительно заявки + текстовое обоснование.
- FR-10. Поиск/фильтрация специалистов по имени, роли, статусу.

### Чат и звонки
- FR-11. Чат владелец ↔ специалист: один диалог на специалиста; статусы сообщений sent/delivered/read.
- FR-12. Специалист получает email (Unisender Go) с magic-ссылкой (токен 30 дней, продлевается новым письмом) на облегчённую страницу чата — без регистрации; там же его назначенные звонки.
- FR-13. Входящие сообщения доставляются в реальном времени через SSE.
- FR-14. Планирование звонка: дата, время, ссылка на встречу; отмена; список предстоящих звонков.
- FR-15. Итог консультации: после звонка владелец отмечает «проведена» и пишет заметку-итог.

### Платежи
- FR-16. Оплата консультации через ЮKassa (карта, встроенная фискализация/чек); redirect-флоу.
- FR-17. Вебхук ЮKassa обновляет статус платежа; статусы: pending → succeeded / canceled; возвраты делает `admin` через ЮKassa, статус refunded приходит вебхуком.
- FR-18. История платежей компании. Комиссия платформы — % из env, фиксируется в записи платежа.

### AI
- FR-19. NewTask: свободный AI-чат (Claude API, Sonnet) с системным контекстом компании; история диалогов сохраняется.
- FR-20. AI-чат в Hiring: помощь по заявкам/кандидатам, генерация черновиков сообщений по шаблонам.
- FR-21. Finance: AI-анализ внесённых записей → список проблем (severity, влияние в ₽).
- FR-22. Marketing: AI-аудит кампаний → рекомендации.
- FR-23. Operations: «запуск» задачи → AI-отчёт о выполнении (без внешних действий).
- FR-24. Лимит токенов на компанию в месяц (env); при исчерпании — понятная ошибка в UI.

### Данные разделов
- FR-25. Finance: CRUD записей (доход/расход, категория, сумма, месяц); графики выручка/прибыль и расходы по категориям — из реальных данных.
- FR-26. Marketing: CRUD кампаний (канал, бюджет, показы, клики, конверсии, период, статус); графики и таблица — из реальных данных.
- FR-27. Operations: CRUD задач (название, описание, расписание-текст); история запусков с отчётами.
- FR-28. Dashboard: реальные KPI (выполнено задач, активные заявки, специалисты в работе, потрачено токенов), последние AI-задачи, уведомления.
- FR-29. Уведомления: новое сообщение от специалиста, предстоящий звонок, успешный платёж; отметка прочитанности, «прочитать все».

### Прочее
- FR-30. Серверные аналитические события (регистрация, создание заявки, оплата и т.д.) в БД + Яндекс.Метрика на фронте.
- FR-31. Soft-delete: специалисты, заявки, диалоги, аккаунт компании (окно 30 дней). Насовсем: финансовые записи, кампании.

## Нефункциональные требования

| # | Требование | Значение |
|---|-----------|----------|
| NFR-1 | Масштаб первого года | ≤500 компаний, ≤50 одновременных пользователей |
| NFR-2 | Инфраструктура | Один VPS в РФ (4 vCPU / 8 ГБ), вертикальное масштабирование |
| NFR-3 | Отклик API | p95 < 300 мс (кроме AI-эндпоинтов — стриминг, первый токен < 3 с) |
| NFR-4 | Персональные данные | Хранение в РФ (152-ФЗ), см. 07 |
| NFR-5 | Доступность | Один инстанс, без HA; допустим даунтайм на деплой < 1 мин |
| NFR-6 | Бэкапы | Ежедневный pg_dump в S3, хранение 30 дней, ежемесячная проверка восстановления |
| NFR-7 | Язык | Только русский; мультиязычность не закладываем |
| NFR-8 | Тесты | С первого дня: Vitest на каждую фичу бэкенда, Playwright e2e на ключевые сценарии |
| NFR-9 | Ошибки | Sentry (API и фронт), структурные логи Pino |
| NFR-10 | Бюджет | ≤15 000 ₽/мес на инфраструктуру и сервисы |

## Out of scope v1 (зафиксировано)

- Командный доступ / несколько пользователей в компании.
- Кабинет специалиста, маркетплейс со стороны специалистов.
- Автоматические выплаты специалистам (payout) — вручную.
- Внешние интеграции: job-боарды, Google Calendar, email-рассылки маркетинга.
- Реальное выполнение операций-автоматизаций (только AI-отчёты).
- Мобильное приложение, адаптив под телефон (десктоп-first).
- Мультиязычность, офлайн-режим, подписки.
