# 09 — Соглашения

## Структура и нейминг

- Пакеты: `@orbital/web`, `@orbital/api`, `@orbital/shared`.
- Файлы: kebab-case (`specialists.service.ts`, `finance-records.repo.ts`); React-компоненты — PascalCase.tsx.
- Суффиксы бэкенда: `*.routes.ts`, `*.service.ts`, `*.repo.ts`; тесты — `*.test.ts` рядом в `test/` c зеркальной структурой.
- Именование в БД/коде — английский; UI-копирайт — русский.
- Деньги везде в переменных с суффиксом `Kopecks`; конвертация в рубли только в UI.
- Хуки TanStack Query: `useXxx` (query), `useCreateXxx`/`useUpdateXxx`/`useDeleteXxx` (mutation).

## TypeScript

- `strict: true` везде; общий `tsconfig.base.json` в корне.
- `any` запрещён (искл. — типы сторонних либ с комментарием); `as` — только с обоснованием.
- Типы API-объектов — только через `z.infer<>` из `@orbital/shared`; вручную не дублировать.

## Git-flow

- Ветки: `main` (защищённая, деплой на staging) + короткие фичевые `feat/T-012-better-auth`,
  `fix/...`. PR в main обязателен, CI зелёный — условие мержа. Один PR ≈ одна задача T-XXX.
- Коммиты: `feat:`, `fix:`, `chore:`, `docs:`, `test:` + номер задачи: `feat(T-018): CRUD заявок`.
- Прод-релиз: тег `vX.Y.Z` с main.
- Никогда: force-push в main, `--no-verify`, коммит `.env`.

## Code style

- Форматирование — `oxfmt` (уже в проекте), запуск в CI.
- Существующий UI-стиль (инлайн-стили + токены из `index.css`) сохраняем; новые экраны — тоже
  токены; Tailwind — только для layout-утилит при необходимости.
- Иконки — только lucide-react, имя проверять.
- Без console.log в прод-коде; на бэке — только logger (Pino).

## Правила слоёв (повтор ключевого)

- routes: HTTP + Zod, ноль бизнес-логики.
- services: вся логика, права через `ctx.companyId`, транзакции `prisma.$transaction`.
- repositories: только Prisma; каждый метод принимает `companyId`; всегда фильтр `deletedAt: null`
  (кроме явных `*Deleted`-методов).
- Внешние сервисы — только через `lib/*`; services не импортируют SDK напрямую.

## Миграции

- Одна миграция = одна задача; имя осмысленное: `add_payment_table`.
- Ломающие изменения в две фазы: (1) добавить новое поле/таблицу + писать в оба места,
  (2) после деплоя и бэкфилла — удалить старое. Между фазами минимум один релиз.
- Правка накативших миграций запрещена — только новая миграция.

## Тесты

- Бэкенд: каждая фича = Vitest-тесты сервиса (юнит с мок-репозиториями — для логики)
  + интеграционный тест роута (реальная тестовая БД, по транзакции на тест).
- Обязательное покрытие: auth-флоу, права (доступ к чужой компании → 404/403), платежи
  (вебхук, идемпотентность), лимит токенов, magic-токен (протухший/чужой).
- lib/ai, lib/payments, lib/email в тестах всегда замоканы; реальные вызовы — только руками.
- e2e Playwright: золотой путь hiring, оплата консультации (тестовый магазин), magic-чат.
- Тест падает → фикс до мержа; скипы только с комментарием-причиной и задачей.

## Документация

- Изменение модели данных/API → обновить 04/05 в том же PR.
- Нетривиальное решение → новый ADR (шаблон в adr/).
- Выполненная задача → статус в PROGRESS.md в том же PR.
